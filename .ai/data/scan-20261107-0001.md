# Ревью vv-db-mcp (повторное)

## 1. Критические баги

**1.1. `src/tools/meta.ts:550-556` — `sample_rows` подставляет в SQL пользовательский регистр, а не имя из каталога.**
- Проверка идёт без учёта регистра (`known.has(col.toLowerCase())`), но в SQL уходит `args.columns`, а не имя из `desc.columns`.
- На Oracle и Firebird имена в каталоге в UPPERCASE. Вызов `columns:["id"]` проходит проверку, затем `quoteIdentifier` даёт `"id"`, и запрос падает с `ORA-00904` или `Column unknown`.
- В PG то же для mixed-case столбцов (`"MyCol"`).
- Комментарий в строках 540-542 и описание в строке 514 обещают обратное.

**1.2. `src/config/load.ts:68-76` — литеральные пароли не маскируются.**
- В `maskSecrets` попадают только значения, **подставленные** через `${KEY}`. Пароль, записанный в конфиг напрямую (`"password": "p@ss"`), в маскер не попадает.
- README:123 утверждает, что «значения секретов из `password`-полей маскируются».
- `test/integration/security.test.ts:53` маскирует по `h.passwords`, собранным из сырого JSON, а не по `registry.secrets`. Поэтому тест проходит и скрывает дыру.

**1.3. `src/tools/meta.ts:277-285` и `418-426` — `list_foreign_keys` и `list_triggers` теряют разрешённую схему.**
- Из `resolveTableRef` берётся только `.name`, а в адаптер передаётся `args.schema`, который может быть `undefined`.
- Пример: таблица `orders` однозначно разрешилась в `sales.orders`, но в базе есть и `hr.orders` (имя неоднозначно лишь без учёта регистра, либо таблица из другой схемы попала под фильтр). Адаптер фильтрует только по имени (`mssql.ts:185`, `pg.ts:208`, `ora.ts:172`), и в ответ попадают FK/триггеры чужой таблицы.
- Нужно передавать `resolved.schema`.

**1.4. `src/catalog/ora.ts:456-475` — `getDefinitions` для процедур и функций склеивает исходники разных владельцев.**
- `byName` ключуется только по `name`.
- Если `schema` не задан и одноимённые процедуры есть у двух owner'ов, строки `all_source` (`ORDER BY s.line`) перемешиваются в один «CREATE OR REPLACE». На выходе — синтаксически бессмысленный текст.

## 2. Проблемы корректности

- **`ora.ts:99,113,123,246,254,291,315,428,451,486`; `fb.ts:140,153,163,296,305,336,361,447…`** — `UPPER(...) = UPPER(:name)` поверх уже точно разрешённого имени.
  - Mixed-case теперь находится, но таблицы `"MyTable"` и `MYTABLE` в одной схеме неотличимы: `describeTable` вернёт объединённые столбцы обеих, `listIndexes` — индексы обеих.
  - Плюс `UPPER(owner)` и `UPPER(table_name)` отключают индексы словаря, что заметно на больших каталогах.
- **`fb.ts:149,187-188`** — `nullable` и `defaultValue` берутся только из `RDB$RELATION_FIELDS`.
  - NOT NULL и DEFAULT, заданные на уровне домена (`f.RDB$NULL_FLAG`, `f.RDB$DEFAULT_SOURCE`), игнорируются, и столбец помечается nullable.
  - Кроме того, `DEFAULT_SOURCE` содержит префикс `DEFAULT `.
- **`fb.ts:22-25` (`FS`)** — BLOB-поля (`RDB$DESCRIPTION`, `RDB$DEFAULT_SOURCE`, `RDB$TRIGGER_SOURCE` в `listConstraints`) идут через `String(v)`. Для `definition` используется `toText`, а здесь нет. Если драйвер отдаёт Buffer или функцию-ридер, получится мусор вместо текста.
- **`pg.ts:41-44` + `common.ts:122`** — массивы в PG.
  - `pgDataType` для `ARRAY` возвращает `udt_name`, то есть `_int4`, а `pgCategory` ожидает суффикс `[]`.
  - В итоге реальные массивы всегда получают `other`, хотя unit-тест (`common.test.ts:31`) проверяет недостижимый формат `integer[]`.
- **`pg.ts:292`, `mssql.ts:265`** — индексы по выражениям.
  - PG: из-за INNER JOIN `pg_attribute` выражение (`attnum = 0`) выпадает. Индекс по одному выражению исчезает целиком, у смешанного теряется часть столбцов. Это противоречит `IndexColumn.name: string | null`.
  - MSSQL уже использует LEFT JOIN.
- **Регистр схем в `resolveName` (`common.ts:41`) несогласован с адаптерами.**
  - `resolveName` сравнивает схему без учёта регистра.
  - Но `mssql.ts:58` и `pg.ts:59` фильтруют `s.name = :schema` / `n.nspname = :schema` точно. Поэтому `schema:"PUBLIC"` даёт пустой листинг и `not_found`, и регистронезависимость в `resolveName` фактически не работает.
- **`exec/params.ts:21-26`** — ошибки конвертации параметров.
  - `as:'date'` с мусором даёт `Invalid Date`, который молча уходит в драйвер.
  - `as:'bigint'` с `"1.5"` бросает `SyntaxError`, и вызов возвращает `internal` вместо `invalid_argument`.
  - `value` при этом не проверяется на `undefined`.
- **`ora.ts:61-65`** — `all_tables` включает контейнерные таблицы materialized views. Это противоречит описанию `list_tables` (`meta.ts:190`).
- **`cli.ts:119-122`** — `uncaughtException` вызывает `process.exit(1)` без `registry.closeAll()`. Пулы Oracle и сессии остаются висеть на стороне СУБД до таймаута.
- **`cli.ts:125`** — `void main()`. Исключение в `server.connect` возникает до установки обработчиков (строки 116-122) и уходит в дефолтный обработчик Node, без маскера.
- **`config/schema.ts`** — нет перекрёстной проверки `timeoutMs ≤ maxTimeoutMs` и `maxRows ≤ maxRowsCap`. Конфиг с инверсией молча клампится вниз.

## 3. Проблемы API и типов

- **`tools/schemas.ts:10-16`** — `limitSchema.max(10000)` и `default(1000)`.
  - Если `maxRowsCap > 10000`, такой лимит в мета-инструментах недостижим.
  - Дефолт листинга не связан с `limits.maxRows` конфига.
- **`tools/index.ts:83-87`** — при ошибке `structuredContent` равен `{ok:false,…}` и не соответствует объявленной `outputSchema` (`ok: z.literal(true)`).
  - SDK пропускает проверку при `isError`, но строгий клиент может отвергнуть ответ.
  - Схема ошибки нигде не объявлена: в `outputSchema` нет union.
- **`catalog/types.ts:122-125`** — у `listIndexes`, `listConstraints` и `describeTable` поле `schema: string | null`, но адаптеры mssql и pg подставляют `'dbo'` / `'public'` при `null` (`mssql.ts:96`, `pg.ts:91`). Контракт неявный.
- **`tsconfig.json:16`** — `include: ["src"]`, поэтому тесты `tsc` не проверяет. Типовые ошибки в `test/` ловятся только в рантайме vitest.

## 4. Риски по модулям

- **catalog/\*.**
  - `resolveTableRef` (`meta.ts:119-131`) на каждый вызов выкачивает полный листинг таблиц и view, а без `schema` — всех схем.
  - Для `describe_table`, `list_indexes` и `list_constraints` это 2–3 полных листинга плюс 3–4 запроса адаптера. На Oracle с десятками тысяч объектов это медленно.
- **catalog/fb.ts:415** — неизвестный `RDB$TRIGGER_TYPE` молча превращается в `after` с `events: []`. Лучше отдавать хотя бы предупреждение.
- **catalog/ora.ts:50,63** — `all_users.oracle_maintained` существует только с Oracle 12c (см. п. 5).
- **exec/run.ts:250** — при `timeout` или `aborted` внутри транзакции `statementIndex` не выставляется, и агент не знает, на каком операторе произошла отмена. Это допустимо, но стоит документировать.
- **Тесты.**
  - Нет unit-тестов `runTx`: `statementIndex`, `computeTxOutcome`, `COMMIT_TIMEOUT`.
  - Нет тестов на `sample_rows` с mixed-case и lowercase столбцами на ora/fb (баг 1.1).
  - Нет тестов на неоднозначность FK/триггеров между схемами и на одноимённые таблицы, различающиеся регистром.
  - Нет теста на маскирование литерального пароля (баг 1.2).

## 5. Расхождения с README и описаниями

- **README:123** — обещано маскирование «password-полей», а маскируются только подставленные `${}` (см. 1.2).
- **README:130** — «Oracle без ограничений по версии», хотя `oracle_maintained` требует 12c+.
- **README:25 / package.json:32** — `connections.example.json` указан в `files`, но в пакете ревью этот файл отсутствует. Проверить, что он реально лежит в репозитории.
- **`meta.ts:190`** — фраза «материализованные объекты исключены» неверна для Oracle (`all_tables`).
- **`meta.ts:514`, `540-542`** — «имена столбцов берутся из каталога» неверно (см. 1.1).

## 6. Что сделано хорошо

- Ключи склейки FK и триггеров теперь `schema.table.name` или `schema.name`. Фильтры одинаково применяются к meta-запросу и запросу столбцов, поэтому полной выборки каталога больше нет.
- `describeTable` в PG переведён на `pg_attribute`: matview и столбцы без привилегий отдаются корректно, есть интеграционный тест.
- `runSql` различает свой abort по maxRows и клиентскую отмену (`run.ts:166`), а реальная ошибка запроса не проглатывается.
- `isTxConnectionLost` построен на явном списке кодов, без широкого `/^E[A-Z]+$/`.
- `classify.ts` учитывает `SELECT … INTO` и DML-CTE.
- В cli: идемпотентный `shutdown` с таймером форса, маскер на всех `console.*`, логирование стека.
- Версия сервера берётся из `package.json`.
- В README появились версии СУБД, обязательные поля и честный список инструментов с `timeoutMs`.
- Есть unit-тесты `runSql` с мок-стримом на ветки maxRows и outcomeUnknown.
