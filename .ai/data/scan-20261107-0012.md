## 2. Проблемы корректности

**2.1. `src/exec/run.ts:269` — возможен `statementIndex: -1`.**
- `currentIndex` инициализируется как `-1` (`run.ts:218`) и меняется только внутри колбэка (`run.ts:240`).
- Если `execTxDynamic` вернёт ошибку с `kind: 'query'` или `'user'` до первого `exec`, клиент получит `statementIndex: -1`. Такое возможно при сбое BEGIN или при пустом колбэке.
- Значение `-1` противоречит README («0-based») и выглядит как индекс оператора.
- Рекомендация: выставлять индекс только при `currentIndex >= 0`.
- Решение 12 касается `timeout`/`aborted` и этот случай не покрывает.

**2.2. `src/exec/params.ts:15,22-24` — `as` вместе с `direction: 'out'` без `value` даёт `invalid_argument`.**
- OUT-параметру значение не нужно. Но если клиент указал тип через `as` (например `as: 'date'` для OUT-даты), `convertValue` бросит «as="date" требует value».
- Рекомендация: пропускать конверсию при `direction === 'out'` и `value === undefined`.

**2.3. `src/exec/params.ts:41` — `BigInt('')` и `BigInt('  ')` возвращают `0n` без ошибки.**
- Пустая или пробельная строка при `as: 'bigint'` превращается в ноль, а не в `invalid_argument`.
- Для DML это тихая подмена значения.
- Рекомендация: отвергать строку, если после `trim()` она пустая.

## 4. Риски по компонентам

**4.1. `src/catalog/mssql.ts:273-274` — columnstore-индексы.**
- Ключевые столбцы columnstore-индекса имеют `key_ordinal = 0`, у некластерного columnstore `is_included_column` бывает `1`.
- Поэтому индекс либо попадёт с непредсказуемым порядком столбцов, либо выпадет целиком.
- Риск редкий, информационно.

**4.2. `src/exec/run.ts:126-130` — `controller.abort()` вызывается на каждой строке сверх `maxRows`.**
- Повторный `abort` безвреден, но `serializeOpts(...)` создаётся на каждую строку (`run.ts:125`).
- Микрооптимизация, информационно.

## 5. Расхождения кода с README/описаниями

- Пункт 2.1: README (строка 123) обещает 0-based `statementIndex`, а код может вернуть `-1`.
- Других расхождений нет.

## 6. Что сделано хорошо

- README:136-137 честно описывает рантайм Node 18 и требование `TZ=UTC`. Оба пункта, переносившиеся из ревью в ревью, закрыты документацией.
- `catalog.test.ts:48-50`: для Oracle передаётся реальный владелец, прямые вызовы адаптера больше не смешивают схемы.
- `runTx` (`run.ts:224-234`): параметры валидируются до BEGIN, и сохраняется `statementIndex` для `invalid_argument`.
- `sample_rows` (`meta.ts:562-569`): имена столбцов берутся из каталога, валидация регистронезависимая. Это корректно и для Oracle/FB, и для mixed-case PG.
- `ora.ts:272-275`: PK-индекс сопоставляется по `index_owner`.
