# Ревью vv-db-mcp (тринадцатый проход)

## 1. Критические баги

Не найдено.

## 2. Проблемы корректности

Новых нет. Все три пункта прошлого ревью закрыты (см. таблицу в конце).

Одно мелкое наблюдение, не баг:

- **`src/errors/map.ts:122-130`**: `formatErrorText` не выводит `connection` в текстовом `content`, хотя поле есть в `structuredContent`.
  - Клиент, который читает только `content`, не узнает, на каком подключении произошёл сбой. Это актуально, когда агент работает с несколькими подключениями параллельно.
  - Стоит добавить строку `connection: …` по аналогии с `code`.

## 3. Проблемы API и типов

- **`src/tools/define.ts:8-11`**: поле `ToolCtx.log` не используется ни одним обработчиком из `service.ts`, `sql.ts` и `meta.ts`.
  - Это не ошибка: оно оставлено как задел.
  - Но сейчас ни одна ошибка инструмента не попадает в stderr даже при `VV_DB_MCP_LOG_LEVEL=debug`. Отладка на стороне оператора возможна только через MCP-клиента.
  - Кандидат на `log.debug` в обёртке `tools/index.ts:81`; сообщение уже маскировано, так как логгер получает маскер.

## 4. Риски по компонентам/модулям

Новых рисков нет. Columnstore-индексы MSSQL (`mssql.ts:273`) и повторный `abort`/`serializeOpts` на каждую строку (`run.ts:124-130`) переведены в принятые решения и здесь не повторяются.

## 5. Расхождения кода с README/доками

Расхождений не найдено.

- README:123 («`statementIndex` 0-based») теперь соответствует коду: `run.ts:269` выставляет индекс только при `currentIndex >= 0`.
- README:113-116 о `timeoutMs`/`maxRows` и капе `sample_rows.limit` согласуется с `meta.ts:571-585`, `sql.ts:36-37,98-99` и `service.ts:59,86`.

## 6. Что сделано хорошо

- **`run.ts:269`**: `statementIndex` защищён от `-1`, есть регрессионный тест `run.test.ts:153-158`.
- **`params.ts:15`**: конверсия `as` пропускается для `direction: 'out'`, тест `params.test.ts:47-50` проверяет, что `value` не выставляется.
- **`params.ts:42-44`**: пустая или пробельная строка при `as: 'bigint'` даёт `invalid_argument`, а не тихий `0n`. Тест `params.test.ts:42-45`.
- **`serialize.ts:40-51,72`**: `Date` и `Uint8Array` проверяются до ветки `toJSON`. Иначе `Buffer.toJSON()` дал бы `{type,data}` вместо `$base64`. Порядок веток корректен.
- **`fb.ts:92-105`**: декодирование `RDB$TRIGGER_TYPE` по формуле. Ручная проверка 1→before/insert и 2→after/insert сходится.
- **Обработка ошибок по слоям**: каталог бросает `ToolFailure`, обёртка `tools/index.ts:81-88` единообразно маскирует. Обработчики не формируют ответ ошибки сами.
