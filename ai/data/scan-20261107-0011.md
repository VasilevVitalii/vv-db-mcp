## 2. Проблемы корректности

**2.1. `src/exec/classify.ts:166-170` — `firstStatementIsWrite` теперь берёт первый оператор, но `isReadOnlyStatement` на нём всё ещё ловит ложные срабатывания.**
- `splitStatements(sql)[0]` исправляет главный дефект прошлого ревью.
- Остаётся ложное «пишет»: `SELECT 'INTO'` или `WITH … SELECT update_ts` (`\bUPDATE\b` не совпадёт, но `SELECT x AS "delete"` совпадёт). Ошибка направлена в безопасную сторону, и это описано в комментарии `classify.ts:44-45`. Информационно.

**2.2. `src/catalog/fb.ts:378` — CHECK в Firebird фильтруется по `RDB$TRIGGER_TYPE = 1`.**
- Firebird создаёт для одного CHECK два системных триггера: BEFORE INSERT (1) и BEFORE UPDATE (3).
- Фильтр по `1` отбрасывает дубли.
- Если CHECK объявлен через `ALTER TABLE … ADD CHECK`, набор триггеров тот же, так что проблемы нет.
- Отмечаю только потому, что интеграционный тест проверяет одно наличие `check` (решение 16). Не блокер.

**2.3. `src/catalog/ora.ts:94-130` — `describeTable` при `schema = null` смешивает владельцев.**
- `resolveTableRef` без схемы возвращает `resolved.schema` с реальным владельцем (из `listTables`). Поэтому через инструменты `null` сюда почти не приходит: `null` бывает только у fb.
- Но `cols`/`pk` при `null` склеили бы столбцы одноимённых таблиц разных владельцев (дубли позиций).
- Через `meta.ts` недостижимо, потому что Oracle-кандидаты всегда несут `owner`. Риск только у прямых вызывающих адаптер (интеграционный тест передаёт `schema: null` для ora: `catalog.test.ts:76`, `DEFAULT_SCHEMA.ora = null`). Если у тестового пользователя есть доступ к одноимённой таблице другой схемы, тест получит дубли столбцов.
- Рекомендация: в тестах передавать текущего владельца.

## 4. Риски по компонентам

**4.1. `src/exec/serialize.ts:40-43` — наивные даты через `toISOString()`** (перенос из прошлого ревью, не закрыт).
- Значения `timestamp without time zone` / `datetime` / Oracle `DATE` при TZ процесса ≠ UTC сдвигаются.
- В README (раздел «Совместимость» или «Конфигурация») нет ни упоминания, ни рекомендации `TZ=UTC`.

**4.2. `package.json:27-29` — `engines: >=18`** (перенос, не закрыт).
- `@types/node ^26`, `typescript ^7` и `vitest ^5` для разработки на Node 18 не годятся.
- В README не уточнено, что Node 18 поддерживается только как рантайм.
- Отдельно: `exec/abort.ts` написан под Node 18, то есть намерение поддерживать 18 есть, а проверки нет.

**4.3. `src/tools/meta.ts:129` — `resolveTableRef` с `includeViews` делает два последовательных запроса.**
- Запросы можно выполнить через `Promise.all`.
- Это микрооптимизация в рамках решения 11. Информационно.

- `run.test.ts:88-151`: покрыты ветка клиентской отмены и сужение NJS-кодов (`NJS-040` / `NJS-500`).
